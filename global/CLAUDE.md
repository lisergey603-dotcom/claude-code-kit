# Общие правила (для всех проектов)

## Общение
- Отвечай по-русски. Код, имена переменных и коммиты — на английском.
- Объясняй коротко и простыми словами. Если термин неочевиден — одна фраза пояснения.
- Перед большой правкой (больше 3 файлов или смена архитектуры) — сначала короткий план, потом работа.
- Если задача неясна и ошибка дорого обойдётся — задай один уточняющий вопрос.

## Как работать с кодом
- Сначала прочитай существующий код и CLAUDE.md проекта, потом пиши. Следуй уже принятому в проекте стилю.
- Маленькие шаги: одно изменение → проверка → следующее.
- Не добавляй зависимости без нужды. Если добавляешь — скажи зачем.
- Не удаляй и не переписывай рабочий код «для красоты», если об этом не просили.
- После правки обязательно проверь: сборка, тесты, линтер — что есть в проекте. Не говори «готово», не проверив.
- Если проверить нельзя (нет SDK, нет доступа) — прямо скажи, что не проверено.

## Безопасность
- Никогда не коммить секреты: токены, пароли, ключи API, keystore, .env.
- Секреты — только через переменные окружения или GitHub Secrets.
- Не выполняй `git push --force`, `rm -rf` и прочие необратимые действия без явной просьбы.

## Git
- Коммиты в стиле Conventional Commits: `feat:`, `fix:`, `refactor:`, `docs:`, `chore:`.
- Одна логическая правка — один коммит.
- Перед коммитом посмотри `git diff` и убедись, что не попало лишнее.

## Окружение
- Android APK собирается в GitHub Actions — локального Android SDK может не быть.
- Если в проекте есть NOTES.md — прочитай его в начале сессии: там последнее состояние работы.
